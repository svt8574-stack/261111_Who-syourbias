# 03. 프론트엔드 기능

## 상태
`start` → `form` → `loading` → `result`; 오류 시 `form` 유지.
- 페이지 전체 새로고침 없이 DOM 상태 전환.
- 방명록 섹션은 상태 전환과 독립적으로 유지.

## 입력 폼
- 내 생년월일 `type=date`, 필수, 1900-01-01~오늘.
- 최애 이름 `type=text`, 필수, trim 후 1~40자.
- 최애 생년월일 `type=date`, 필수, 동일 범위.
- 양력만 지원한다는 안내.
- 분석 클릭 시 중복 요청 차단; 버튼 비활성화 및 로딩.
- 클라이언트와 서버 모두 유효성 검증.
- `POST /api/analyze` body:
```json
{"myBirthDate":"2001-05-12","biasName":"예시 최애","biasBirthDate":"2000-08-21"}
```

## 결과 렌더링
- 서버 반환 오행 한글/한자, 상징, 관계 이름, 점수, 등급 표시.
- 해설, 연애 가정, 결혼 가정은 일반 텍스트로 출력.
- 연애/결혼 문구 각각 공백 포함 150자 이내.
- 점수나 오행은 프론트에서 임의로 계산/수정하지 않음.
- 결과 하단: '간이 오행 테스트로 실제 관계를 예측하지 않습니다.'

## 다시 분석하기
- 결과 및 폼 입력 초기화, 상태 `form`으로 전환, 첫 입력칸 포커스.
- 방명록 목록/작성 상태는 변경하지 않음.

## 토스트
- 상단 `role=alert`(오류), 성공은 `role=status`.
- 오류 시 ⚠️ + 설명, 성공 시 ✓ + 설명.
- 3000ms 후 숨김. 새 토스트가 오면 이전 타이머 취소.
- 중요 입력 오류는 해당 입력 아래에도 설명 표시.
- 네트워크 오류 시 사용자 입력 보존.

## 방명록
- 입력: nickname(2~15자), message(1~300자).
- 제출: `POST /api/feedback`; 성공 시 내용 초기화 후 목록 다시 요청.
- `GET /api/feedback?limit=50&offset=0` 로 최신순 표시.
- 50개씩 '더 보기'로 이어서 불러와 **모든 글에 접근 가능**하도록 구현.
- `created_at`은 로컬 날짜/시간으로 읽기 쉽게 표시.
- 각 글의 프로필 아이콘은 ❤️ 고정.
- 반드시 `textContent` 사용. `innerHTML`로 사용자 글 출력 금지.
- 전송 중 버튼 비활성화.

## 예외 처리
- API 응답 `ok=false` 또는 HTTP 오류 시 사용자 친화적 토스트.
- AI 실패 시 가짜 결과를 표시하지 않고 재시도 안내.
- 방명록 읽기 실패 시 '목록을 불러오지 못했어요' + 재시도 버튼.
