# 04. 백엔드·오행·OpenAI 구현

## 간이 오행 계산 규칙 (정확히 고정)
- 입력은 **양력 출생연도 YYYY만 사용**. 월/일은 날짜 유효성 검사에만 사용.
- **입춘 기준 미적용**. 이는 실제 사주 년주 계산과 다를 수 있는 교육용 간이 분류.
- 출생연도 끝자리와 천간/오행 매핑:
  - 0 경(庚) 금(金)
  - 1 신(辛) 금(金)
  - 2 임(壬) 수(水)
  - 3 계(癸) 수(水)
  - 4 갑(甲) 목(木)
  - 5 을(乙) 목(木)
  - 6 병(丙) 화(火)
  - 7 정(丁) 화(火)
  - 8 무(戊) 토(土)
  - 9 기(己) 토(土)
- 상징: 목 성장, 화 열정, 토 안정, 금 결단, 수 유연.
- **생년월일 전체를 사용하는 정통 사주 분석이라고 표현 금지.**

## 오행 관계
상생 순환: 목→화→토→금→수→목.
상극 순환: 목→토→수→화→금→목.
- 나와 최애가 동일: `동일 오행`, 80점.
- 나→최애 상생: `내가 최애를 돕는 상생`, 90점.
- 최애→나 상생: `최애가 나를 돕는 상생`, 90점.
- 나→최애 상극: `내가 최애를 제어하는 상극`, 55점.
- 최애→나 상극: `최애가 나를 제어하는 상극`, 55점.
- 두 오행은 위 5가지 중 반드시 하나에 해당한다. **점수는 실제 궁합 확률이 아니라 게임 규칙**.
- 등급: 90~100 `환상의 케미`, 75~89 `반짝이는 케미`, 60~74 `서로 다른 매력`, 40~59 `색다른 케미`, 0~39 `새로운 발견`.
- 점수/관계/등급은 서버 함수로 결정, GPT 출력으로 덮어쓰지 않는다.
- 방향을 바꿔 입력해도 점수는 같고 상생/상극 방향 설명만 바뀐다.

## API 계약
### POST /api/analyze
요청:
```json
{"myBirthDate":"2001-05-12","biasName":"예시 최애","biasBirthDate":"2000-08-21"}
```
성공(예시):
```json
{
  "ok":true,
  "data":{
    "myElement":{"name":"금","hanja":"金","symbol":"결단"},
    "biasElement":{"name":"금","hanja":"金","symbol":"결단"},
    "relation":"동일 오행",
    "score":80,
    "grade":"반짝이는 케미",
    "headline":"비슷한 리듬으로 빛나는 우리",
    "description":"...",
    "datingScenario":"...",
    "marriageScenario":"...",
    "disclaimer":"양력 출생연도 기준 간이 오행 테스트입니다."
  }
}
```
실패: `{"ok":false,"error":"사용자가 이해할 수 있는 메시지"}` + 적절한 HTTP 상태 코드.
- 클라이언트 입력을 서버에서 재검증(실제 날짜, 길이, 허용 범위).
- API 타임아웃과 호출 실패 처리.
- 로그에 원문 입력·API 키 출력 금지.

## GPT-4o mini 호출
- 서버에서만 `OPENAI_API_KEY` 사용.
- `model: "gpt-4o-mini"` 지정.
- 모델은 **해설만** 생성. 서버 계산값(오행·관계·점수·등급)은 읽기 전용 데이터.
- JSON 출력 필드: `headline`, `description`, `datingScenario`, `marriageScenario`.
- Structured Outputs JSON Schema 사용 가능하면 적용; 결과를 서버에서 필수 문자열/길이 검증.
- `datingScenario` 및 `marriageScenario`는 각각 **공백 포함 JavaScript 문자열 길이 150 이하**로 검증; 초과 시 재생성 1회, 계속 실패하면 오류 처리(임의 잘라내기로 문장 훼손하지 않음).
- `headline` 40자 이내, `description` 300자 이내.
- 응답에 점수/오행이 들어오더라도 사용하지 않음.

## 모델 시스템 지시문 예시
> 너는 팬덤형 간이 오행 궁합 테스트의 한국어 콘텐츠 작가다. 입력으로 제공된 오행, 관계, 점수, 등급을 바꾸거나 새로 계산하지 마라. 연예인의 실제 감정·성격·관계 성사 가능성을 단정하지 마라. 실제 미래 예언이 아닌 상상 속 상황을 밝고 귀엽게 묘사하라. 연애 시나리오는 데이트·설렘 중심, 결혼 시나리오는 일상·배려 중심으로 서로 다르게 작성하라. 각각 공백 포함 150자 이내. 지정된 JSON 필드만 반환하라.

## 일관성
- 동일 입력 → 오행/관계/점수/등급 동일.
- AI 해설 문장은 호출마다 달라질 수 있음.
- OpenAI 실패 시 오류 토스트로 안내, 계산값은 꾸며서 반환하지 않음.
